## 一、项目概述

AI Film 是一款 AI 驱动的影片创作平台，支持多模态内容生成（图片、视频、音频）、多人实时协作编辑、灵活的订阅计费系统。

### 1.1 核心技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | React + TypeScript + Vite + TailwindCSS | 当前 |
| 后端 | Node.js + Express + Socket.io | 当前 |
| 数据库 | MySQL | 当前 |
| 文件存储 | 腾讯云 COS | 当前 |
| 队列系统 | Redis + Bull/BullMQ | 待接入 |
| 容器化 | Docker + Docker Compose | 当前 |

### 1.2 当前部署

- 后端服务: `http://localhost:3001`
- 前端开发: `http://localhost:5173`
- 数据库: MySQL `openfilm`

## 四、队列系统架构

> ⚠️ **重要**: 当前系统为单用户同步调用，多用户场景下必须引入任务队列系统。

### 4.1 为什么需要队列系统

| 场景 | 问题 | 解决方案 |
|------|------|----------|
| 多用户并发 | 同时多人生成视频，后端压力过大 | 队列+并发控制 |
| 视频生成耗时 | 视频生成需要 1-5 分钟，同步等待不现实 | 异步任务+进度推送 |
| API 限流 | 各厂商有 QPS/TPM 限制 | 队列+限流器 |
| 失败重试 | 网络波动导致生成失败 | 自动重试机制 |
| 资源释放 | 用户关闭页面，任务仍在执行 | 任务取消+资源清理 |
| 积分扣除 | 生成成功才扣费 | 预扣费+失败回退 |

### 4.2 队列架构设计

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   前端      │────▶│  API 网关   │────▶│   队列      │
│  (WebSocket)│◀────│  (Express)  │◀────│  (BullMQ)   │
└─────────────┘     └─────────────┘     └─────────────┘
                           │                   │
                           ▼                   ▼
                    ┌─────────────┐     ┌─────────────┐
                    │   Redis     │     │  Worker     │
                    │  (缓存/会话) │     │ (任务执行)  │
                    └─────────────┘     └─────────────┘
                                               │
                                               ▼
                                        ┌─────────────┐
                                        │  第三方 API  │
                                        │ (火山/OpenAI)│
                                        └─────────────┘
```

### 4.3 队列功能清单

| 功能 | 优先级 | 工时 | 说明 |
|------|--------|------|------|
| Redis + BullMQ 集成 | P0 | 2天 | 队列基础设施 |
| 任务状态管理 | P0 | 1天 | pending/running/completed/failed |
| WebSocket 进度推送 | P0 | 1天 | 实时更新任务状态 |
| 并发控制 | P0 | 1天 | 限制同时执行任务数 |
| 优先级调度 | P1 | 1天 | 付费用户优先 |
| 失败自动重试 | P1 | 1天 | 指数退避策略 |
| 任务取消 | P1 | 0.5天 | 用户主动取消 |
| 预扣费机制 | P1 | 1天 | 生成前扣积分 |
| 死信队列 | P2 | 0.5天 | 失败任务处理 |
| 任务超时处理 | P2 | 0.5天 | 防止任务卡死 |

**队列系统工作量**: 10人日
